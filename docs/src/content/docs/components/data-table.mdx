## What it's for

For looking up an exact figure, and for reading every value in a chart without a mouse. Each chart that matters gets one.

## When not to use it

- **Words about what changed.** Use an [outcome table](/components/outcome-table/).
- **Under three rows.** Say it in a sentence.
- **Filters, pagination and row selection.** This reads figures. Those need a real data grid, and there's nothing here yet that needs one.

## Anatomy

- **Caption:** optional, what the table holds.
- **Header:** the label and, in muted text, the unit. Sortable headers are buttons.
- **Rows:** 40px, or 32px with `density="compact"`.
- **Scroll area:** it scrolls sideways on its own when it doesn't fit, so the page never does.

## Variants

| Prop | Does |
|---|---|
| `density` | `default`, `compact` (32px), or `comfortable` (56px with more air, for a list read row by row). |
| `stack` | Below 640px each row becomes a card instead of scrolling sideways. A cell's `.stack-label` shows only then; class `stack-hide` hides a cell then. |
| `loading` | Starts with placeholder rows in the table's shape. |
| `empty`, `failed` slots | Shown instead of the body when there's nothing, or it failed: an [empty state](/components/empty-state/) or [Load failed](/components/load-failed/). |
| `align`, per column | `right` by default, for numbers. `left` for words. |
| `wrap`, per column | Off by default. On for words that can run long, such as a name or a description, so the figures stay in view on a phone. |
| `sortable`, per column | On by default. `false` for a column with nothing to compare. |

## States

| State | What shows |
|---|---|
| Hover | A tint on the row. Off the path if you never hover. |
| Sorted | An arrow on that column only, and `aria-sort`. |
| Empty cell | A dash. Empty rows sort last either way. |
| Loading | Placeholder rows in the table's shape, after 300ms so a fast load shows nothing. A soft sweep, still under reduced motion. `aria-busy` on the body. |
| Whole table empty | The `empty` slot instead of the body, or an [empty state](/components/empty-state/) instead of the table. |
| Failed | The `failed` slot instead of the body. |

## Keyboard and screen reader

- **A real `table`,** with `scope="col"` and `aria-sort`.
- **Sort buttons are in the tab order,** and Enter or Space sorts: descending first, then ascending.
- **The scroll area can take focus,** so a keyboard can scroll it.
- **The scroll area is a named region.** It takes the caption's words, or `label` when the table sits in a figure whose title already says what it is. Two tables on a page need different names.

## Content

- **Units go in the header,** so cells hold only the number.
- **Numbers are right-aligned and mono, words left-aligned in the body face.** Tabular figures make columns line up.
- **Dutch number format.**
- **Only words wrap.** A figure on two lines is misread, so number columns never do.

```astro wrap
import DataTable from '@n1kname/components/DataTable.astro';

<DataTable
  columns={[{ label: 'Room', align: 'left' }, { label: 'Peak', unit: 'ppm' }]}
  rows={[['Alder', 1040], ['Birch', null]]}
/>

<!-- Or fill it at runtime -->
<DataTable id="weeks" columns={columns} />
<script>
  import { setRows } from '@n1kname/components/datatable.js';
  setRows(document.getElementById('weeks'), rows);
</script>
```

## Loading, empty and failed

<div class="not-content">
  <DataTable
    density="comfortable"
    stack
    loading
    loadingRows={3}
    caption="Fictional rooms, still loading"
    columns={[
      { label: 'Room', align: 'left', wrap: true },
      { label: 'Floor', align: 'left' },
      { label: 'Average', unit: 'ppm' },
    ]}
  />
</div>

A table filled at runtime starts with `loading`, then `setRows()` ends it: with rows it's ready, with none it shows the `empty` slot. `setState(table, 'failed')` shows the `failed` slot, and `setState(table, 'loading')` brings the placeholders back for a reload.

```astro wrap
<DataTable id="rooms" density="comfortable" stack loading columns={columns}>
  <EmptyState slot="empty" kind="filtered" title="No rooms match these filters"><Button variant="quiet">Clear filters</Button></EmptyState>
  <LoadFailed slot="failed" title="Couldn't load the rooms" />
</DataTable>
<script>
  import { setRows, setState } from '@n1kname/components/datatable.js';
  const table = document.getElementById('rooms');
  fetch('/api/rooms').then((r) => r.json()).then((rooms) => setRows(table, rooms.map(toRow))).catch(() => setState(table, 'failed'));
</script>
```

## Keep in mind

- **A cell can be `{ html, sort }`,** to show something other than what it sorts by. `html` is written as is, so escape anything from outside with `esc` from `datatable.js`.

## Columns from data, and long tables

- **`setColumns(table, columns)`** from `datatable.js` writes the header when the columns are known only at runtime (a column per type that appears, say). They sort as the built ones do; then `setRows()` as ever.
- **`height`** puts a long table in a scrolling region of its own, such as `height="min(70vh, 640px)"`, with the header staying in view. What follows the table stays where it is while rows arrive.
- **A row that opens something:** put a button in its first cell (the keyboard's way in) and listen for clicks on the row; open the detail with `openPanel()` from [Side panel](/components/side-panel/).

```js
import { setColumns, setRows } from '@n1kname/components/datatable.js';
setColumns(table, [{ label: 'Year', align: 'left' }, ...types.map((t) => ({ label: t }))]);
setRows(table, rows);
```
